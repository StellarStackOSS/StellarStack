This walkthrough stands up the **panel** (web UI + API + Postgres + Redis)
and a **daemon** node on the same machine, then creates one Minecraft
server. It's the fastest way to confirm StellarStack works on your box
before you commit to a multi-node deployment.

<Note>
  For a production setup with the panel and daemons on separate hosts,
  read [Self-hosting → Install](/self-hosting/install) instead.
</Note>

## Prerequisites

<Check>A 64-bit Linux box with `sudo` access (Ubuntu 22.04+, Debian 12+, or any modern systemd distro)</Check>
<Check>Docker Engine 24+ already installed and running</Check>
<Check>4 GB RAM minimum (8 GB recommended for the all-in-one quickstart)</Check>
<Check>Ports `80`, `443`, and `8443` available on the public interface</Check>

If Docker isn't there yet, run `curl -fsSL https://get.docker.com | sh`
and continue once `docker info` works without `sudo`.

## 1. Run the installer

<CodeGroup>

```bash one-line
curl -fsSL https://get.stellarstack.dev | sudo bash
```

```bash with-args
curl -fsSL https://get.stellarstack.dev | \
  sudo bash -s -- --domain panel.example.com --email you@example.com
```

</CodeGroup>

The installer:

1. Creates `/opt/stellarstack/` and pulls the panel + daemon containers.
2. Generates a self-signed cert (or requests one via Let's Encrypt if you
   passed `--domain`).
3. Boots Postgres, Redis, the API, and the daemon under `systemd`.
4. Prints the admin email + a generated password on completion.

<Tip>
  The installer is idempotent — re-running it upgrades to the latest
  release without nuking your data.
</Tip>

## 2. Sign in

Open `https://panel.example.com` (or `https://<your-ip>:8443` for IP-only
installs) and sign in with the credentials the installer printed.

You'll land on an empty dashboard. The next two steps fix that.

## 3. Pair the local daemon

The all-in-one installer pre-pairs the local daemon for you. To check:

1. Open **Admin → Nodes**.
2. You should see one node named `local` with status **online**.

If you don't, follow [Pair a node](/self-hosting/pair-node) — it's a
two-command process.

## 4. Install your first blueprint

Blueprints are install scripts + runtime config + readiness probes for a
specific game. The installer ships a few defaults; pull more from the
catalog.

1. **Admin → Blueprints → Import from catalog**.
2. Select **Minecraft (Paper)**.
3. Click **Install** — the panel fetches the blueprint definition.

## 5. Create a server

1. **Servers → New**.
2. Name: `quickstart`.
3. Blueprint: **Minecraft (Paper)**.
4. Allocation: pick one of the auto-generated `0.0.0.0:25565` rows.
5. Memory: 2 GB. Disk: 5 GB.
6. **Create** — the install script runs in the background; the row
   shows **Installing** until it's ready (≈30s for Minecraft).

## 6. Start it

When the row goes to **Offline**, click into it and hit **Start**. Watch
the console stream in real time. The status flips to **Running** when
Paper logs `Done!` (the blueprint's console-done pattern).

Connect a Minecraft client to your panel's public IP on port 25565 — your
server is live.
