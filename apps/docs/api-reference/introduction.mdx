The StellarStack API is the same one the panel UI talks to. Anything
the UI can do, the API can do.

## Base URL

```
https://panel.example.com/api
```

Hosted product: `https://stellarstack.dev/api`. Self-hosted: whatever
`PANEL_URL` you configured.

## Format

- Requests: `Content-Type: application/json` for bodies; query strings
  for filtering.
- Responses: `application/json`. UTF-8.
- Verbs: `GET`, `POST`, `PATCH`, `DELETE`. No `PUT`.
- Versioning: pinned to the panel image version. Breaking changes are
  called out in release notes.

## Authentication

Bearer tokens — see [Authentication](/api-reference/authentication).

```bash
curl https://panel.example.com/api/servers \
  -H "Authorization: Bearer ssk_live_..."
```

## Error envelope

Failed requests return:

```json
{
  "ok": false,
  "error": {
    "code": "validation.invalid",
    "params": { "field": "name" }
  }
}
```

The `code` is a stable string from the [error codes](/api-reference/errors)
catalogue. `params` carry context for the i18n message. The HTTP status
gives you the family (`4xx` client / `5xx` server); the `code` gives
you the specifics.

## Pagination

List endpoints use cursor pagination:

```
GET /servers?limit=50&cursor=eyJpZCI6...
```

```json
{
  "data": [ /* items */ ],
  "nextCursor": "eyJpZCI6..."   // null when at the end
}
```

`limit` defaults to 50, max 200.

## Idempotency

`POST` routes that create resources accept an `Idempotency-Key` header.
A key seen within 24 hours returns the original response without
re-executing.

## Rate limits

Per-token: 1000 requests / minute. Per-IP: 5000 requests / minute. Hit
either, get `429 Too Many Requests` with a `Retry-After` header.

The browser-direct daemon WebSocket is **not** rate-limited at the
panel layer — only its open count is (5 concurrent per server per
token).
