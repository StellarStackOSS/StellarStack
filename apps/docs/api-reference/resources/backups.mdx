title: "Backups"
description: "Create, list, restore, lock, delete server backups."

---

Backups are nested under a server. Routes are gated by `backups.*`
scopes — see [Permissions](/multi-tenant/permissions).

## List

```http
GET /api/servers/:id/backups
```

```json
{
  "backups": [
    {
      "id": "...",
      "serverId": "...",
      "name": "scheduled-2026-05-09",
      "storage": "local",
      "state": "ready",
      "bytes": 1573912834,
      "locked": false,
      "createdAt": "2026-05-09T04:00:01Z",
      "completedAt": "2026-05-09T04:01:14Z"
    }
  ]
}
```

Required scope: `backups.read`.

## Create

```http
POST /api/servers/:id/backups
Content-Type: application/json

{
  "name": "pre-update",
  "destinationId": null
}
```

If `destinationId` is null, the backup goes to local disk. Pass an S3
destination ID (created via `POST /servers/:id/destination`) to push to
S3 instead.

The response returns immediately with the new row in `state=pending`.
Poll the list endpoint to watch it move to `ready` or `failed`.

Required scope: `backups.create`.

## Restore

```http
POST /api/servers/:id/backups/:backupId/restore
Content-Type: application/json

{
  "snapshotBeforeRestore": true
}
```

`snapshotBeforeRestore: true` (recommended) creates a fresh backup of
the current state before the restore overwrites files. Restore is
synchronous — the call returns when files are in place. The server is
left in `offline`; start it explicitly.

Required scope: `backups.restore`. Server must not be `running`.

## Lock / unlock

```http
POST /api/servers/:id/backups/:backupId/lock
Content-Type: application/json

{ "locked": true }
```

Locked backups can't be deleted — by users, by retention policy, or by
schedule rotation. Unlock the same way with `locked: false`.

Required scope: `backups.lock`.

## Delete

```http
DELETE /api/servers/:id/backups/:backupId
```

Removes the row + the archive file. Refused if the row is `locked`.

Required scope: `backups.delete`.

## Download

```http
GET /api/servers/:id/backups/:backupId/download
```

For local backups: returns a `302` to a daemon-direct presigned URL
that streams the archive. For S3-backed backups: returns a presigned
S3 URL.

In both cases, the URL is valid for 5 minutes.

Required scope: `backups.read`.

## S3 destinations

```http
PUT /api/servers/:id/destination
Content-Type: application/json

{
  "endpoint": "https://s3.eu-west-1.amazonaws.com",
  "region": "eu-west-1",
  "bucket": "stellar-backups",
  "prefix": "minecraft-survival/",
  "accessKey": "AKIA...",
  "secretKey": "..."
}
```

Returns the destination ID. Use it as `destinationId` on subsequent
backup creates.

Delete with `DELETE /api/servers/:id/destination` — drops the credentials
and reverts new backups to local-only.

The secret key is encrypted at rest (using `DAEMON_SIGNING_SECRET` as
the KEK) and never returned by GET.
