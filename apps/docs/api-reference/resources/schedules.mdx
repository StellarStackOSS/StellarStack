Schedules are nested under a server. The wire shape carries the **flow
graph** (nodes + edges); the runner walks the graph from the trigger
node when the cron fires. See [Schedules](/operations/schedules) for
the conceptual model.

## Wire shape

A schedule looks like:

```json
{
  "id": "...",
  "serverId": "...",
  "name": "Nightly backup",
  "cron": "0 4 * * *",
  "enabled": true,
  "onlyWhenOnline": false,
  "nextRunAt": "2026-05-10T04:00:00Z",
  "lastRunAt": "2026-05-09T04:00:00Z",
  "createdAt": "2026-04-01T12:00:00Z",
  "flow": {
    "nodes": [
      {
        "id": "<uuid>",
        "kind": "trigger",
        "subtype": "cron",
        "payload": {},
        "position": { "x": 0, "y": 0 }
      },
      {
        "id": "<uuid>",
        "kind": "action",
        "subtype": "power.stop",
        "payload": {},
        "position": { "x": 0, "y": 120 }
      }
    ],
    "edges": [
      { "fromNodeId": "<id>", "toNodeId": "<id>" }
    ]
  }
}
```

## Subtypes

| Kind      | Subtype             | Payload                                        |
| --------- | ------------------- | ---------------------------------------------- |
| `trigger` | `cron`              | `{}` (cron lives on the schedule row).         |
| `action`  | `power.start`       | `{}`                                           |
| `action`  | `power.stop`        | `{}`                                           |
| `action`  | `power.restart`     | `{}`                                           |
| `action`  | `power.kill`        | `{}`                                           |
| `action`  | `backup.create`     | `{ "name"?: string }`                          |
| `action`  | `console.send`      | `{ "line": string }`                           |
| `wait`    | `state.online`      | `{ "timeoutSeconds"?: number }` (default 300)   |
| `wait`    | `state.offline`     | `{ "timeoutSeconds"?: number }` (default 120)  |
| `wait`    | `backup.complete`   | `{ "timeoutSeconds"?: number }` (default 1800) |
| `wait`    | `delay.seconds`     | `{ "seconds": number }`                         |

## List

```http
GET /api/servers/:id/schedules
```

Returns all schedules with their flows expanded.

Required scope: `schedules.read`.

## Create

```http
POST /api/servers/:id/schedules
Content-Type: application/json

{
  "name": "Nightly backup",
  "cron": "0 4 * * *",
  "enabled": true,
  "onlyWhenOnline": false,
  "flow": {
    "nodes": [ /* … */ ],
    "edges": [ /* … */ ]
  }
}
```

Validation:

- Exactly one `trigger` node, no incoming edges.
- All `edges` reference existing node IDs.
- No cycles.
- All nodes reachable from the trigger.

Failures return `400` with `code = validation.invalid`.

Required scope: `schedules.write`.

## Update

```http
PATCH /api/servers/:id/schedules/:scheduleId
Content-Type: application/json
```

Same body as create. The `flow` is replaced wholesale — there's no
in-place node/edge editing.

## Delete

```http
DELETE /api/servers/:id/schedules/:scheduleId
```

Cascades through the nodes + edges.

## Force-run

```http
POST /api/servers/:id/schedules/:scheduleId/run
```

Fires the schedule's flow once, immediately, regardless of cron.
Returns `202 Accepted` with a `runId` you can poll (the run itself is
async).

Required scope: `schedules.execute`.
