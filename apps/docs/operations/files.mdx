The file manager is a thin UI over the daemon's file API. Like the
console, it's browser-direct: large uploads stream to the daemon node,
not through the panel.

## What you can do

| Action                  | Notes                                                                 |
| ----------------------- | --------------------------------------------------------------------- |
| Browse                  | Hierarchical view rooted at the server's bind-mount.                  |
| Open / edit             | Monaco editor for text files (≤ 5 MB by default).                     |
| Upload                  | Drag-and-drop. Multi-file. Streams direct to daemon.                  |
| Download                | Single file or zipped folder.                                         |
| Rename / move           | Atomic on the daemon's filesystem.                                    |
| Decompress              | `.zip`, `.tar`, `.tar.gz`, `.tar.zst`. Extracted in-place.            |
| Permissions             | View only — Docker bind-mount is uid-mapped to the container's user. |

## Editing files

Click any text file to open Monaco. Save with **Ctrl+S** (or **Cmd+S**).
The save round-trips through the daemon's PUT endpoint and writes
atomically (temp file + rename), so partial writes don't corrupt
existing files if the browser disconnects.

The editor opens at line 1, not at the end of file — this matters
because Monaco defaults to landing at the bottom on long files. We
override that explicitly.

## Decompression

Right-click an archive → **Decompress**. The daemon spawns a
short-lived helper process inside a sandbox; output writes to the
current directory. Failures roll back partial extraction.

Supported formats:

- `.zip`
- `.tar`
- `.tar.gz` / `.tgz`
- `.tar.zst`

Bigger formats? Use SFTP and decompress on the host — see
[SFTP](/operations/sftp).

## Limits

| Limit                          | Default     | Tunable in              |
| ------------------------------ | ----------- | ----------------------- |
| In-browser editor file size    | 5 MB        | `daemon.toml`           |
| Single upload size             | 2 GB        | `daemon.toml`           |
| Decompression target size      | 10 GB       | `daemon.toml`           |
| Concurrent file API requests   | 4 / browser | hard-coded              |

For larger uploads or transfers, SFTP is the right tool.

## Path safety

The daemon refuses paths that:

- Escape the server's root via `..`.
- Resolve through symlinks pointing outside the root.
- Touch any file the container's user can't read on disk.

If you see "permission denied" in the panel but the file looks fine via
SFTP, the difference is usually the daemon's safety check, not Linux
permissions.

## Subuser access

The relevant scopes are `files.read` and `files.write`. A subuser with
read but not write can browse and download but not upload, edit, or
delete. See [Permissions](/multi-tenant/permissions).
