StellarStack ships releases roughly every 2–3 weeks. The installer is
upgrade-aware — re-running it pulls the latest panel image, runs
migrations, and restarts the service.

## Bundled installs

```bash
curl -fsSL https://get.stellarstack.dev | sudo bash
```

The installer:

1. Pulls `ghcr.io/stellarstackoss/panel:latest`.
2. Runs Drizzle migrations against your existing database.
3. Restarts `stellar-panel.service`.

It does **not** touch user data — Postgres, Redis, and the daemon-side
volumes are left alone.

## Daemons

Daemons follow the same pattern:

```bash
curl -fsSL https://get.stellarstack.dev | sudo bash -s -- --role daemon
```

Daemon updates restart `stellar-daemon.service` which transiently kills
the WebSocket sessions for any browser viewing console at that exact
moment. Game-server containers keep running — the daemon doesn't
restart them.

## Bring-your-own deploys

If you didn't use the installer, pull the new image and run:

```bash
docker pull ghcr.io/stellarstackoss/panel:latest
docker stop stellar-panel && docker rm stellar-panel
docker run -d --name stellar-panel \
  --env-file /opt/stellarstack/.env \
  -p 8000:8000 \
  ghcr.io/stellarstackoss/panel:latest
```

Migrations run automatically on boot.

## Rollbacks

We tag every release on GHCR with both `latest` and a semver tag
(`v1.4.2`). To roll back:

```bash
docker pull ghcr.io/stellarstackoss/panel:v1.4.1
docker stop stellar-panel && docker rm stellar-panel
docker run -d --name stellar-panel \
  --env-file /opt/stellarstack/.env \
  -p 8000:8000 \
  ghcr.io/stellarstackoss/panel:v1.4.1
```

<Warning>
  Down-migrations are **not supported**. If `v1.4.2` ran a destructive
  migration you can't go back to `v1.4.1` cleanly without restoring a
  Postgres backup. The release notes for any breaking migration call this
  out at the top.
</Warning>

## Release channels

| Channel       | Tag suffix    | Cadence       | Risk |
| ------------- | ------------- | ------------- | ---- |
| **Stable**    | `:latest`     | Every 2–3 weeks | Low  |
| **Beta**      | `:beta`       | Weekly        | Medium |
| **Edge**      | `:edge`       | Every commit  | High |

Most operators stay on `:latest`. Beta is fine for community installs
that want to dogfood the next release; edge is for contributors.
