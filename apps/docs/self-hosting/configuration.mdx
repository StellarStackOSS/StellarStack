StellarStack is configured by environment variables on the panel and a
TOML file on each daemon. Anything that can't be configured by env or
TOML lives in the database and is editable through the admin UI.

## Panel env vars

The panel container reads `/opt/stellarstack/.env`. Required vars:

| Variable                  | Required | Default   | Description                                                           |
| ------------------------- | :------: | --------- | --------------------------------------------------------------------- |
| `DATABASE_URL`            | ✅       | —         | Postgres connection string. Drizzle auto-runs migrations on boot.     |
| `REDIS_URL`               | ✅       | —         | Redis connection string. Used for session store + status cache.       |
| `SESSION_SECRET`          | ✅       | —         | 32-byte hex secret for cookie signing. Rotate ⇒ all sessions invalidated. |
| `DAEMON_SIGNING_SECRET`   | ✅       | —         | 32-byte hex secret used as the master HMAC for daemon JWTs.          |
| `PANEL_URL`               | ✅       | —         | Public URL the panel is served from. Used in emails + JWT claims.    |
| `SMTP_HOST`               | ✅       | —         | Outbound SMTP relay.                                                  |
| `SMTP_PORT`               | ⚠️       | `465`     | TLS by default; set `587` for STARTTLS.                              |
| `SMTP_USER` / `SMTP_PASS` | ⚠️       | —         | Required if your SMTP needs auth (most do).                          |
| `SMTP_FROM`               | ✅       | —         | Display address for transactional email.                             |
| `LOG_LEVEL`               | ❌       | `info`    | `debug` for development, `warn` for noisy installs.                  |

Optional integrations:

| Variable                  | Required | Default   | Description                                                           |
| ------------------------- | :------: | --------- | --------------------------------------------------------------------- |
| `STRIPE_SECRET_KEY`       | ❌       | —         | Required only on hosted-SaaS deployments.                             |
| `OPENAI_API_KEY`          | ❌       | —         | Powers the Ask AI feature in the console. Anthropic key also works.   |
| `OBSERVABILITY_DSN`       | ❌       | —         | Sentry-compatible DSN if you want crash reports.                      |

## Daemon TOML

Per-daemon config lives at `/etc/stellar-daemon/config.toml`. Created by
`stellar-daemon configure`; rarely needs hand-editing.

```toml
node_id = "d4f8c1a8-..."
panel_url = "https://panel.example.com"
listen = "0.0.0.0:8443"
data_dir = "/var/lib/stellar"
docker_socket = "/var/run/docker.sock"

[tls]
mode = "letsencrypt"      # or "static" or "off"
domain = "mc-eu-1.example.com"
email = "ops@example.com"

[signing]
key = "<hex>"             # populated by `configure`; do not share
```

After editing, `sudo systemctl restart stellar-daemon`.

## Database-driven settings

Anything the panel admin needs to tune at runtime lives in Postgres,
editable via **Admin → Settings**:

| Setting                  | Default          | Notes                                                  |
| ------------------------ | ---------------- | ------------------------------------------------------ |
| Default backup retention | 30 days          | Per-server override available.                         |
| Console replay buffer    | 150 lines        | Sent to browsers on (re)connect.                       |
| Install timeout          | 30 minutes       | Bigger games (e.g. Conan Exiles) need 60+.             |
| 2FA enforcement          | Optional          | Switch to **Required** to lock out users without TOTP. |
| Public registration      | Disabled         | Admins create users.                                   |
| Default user limits      | 5 servers, 50 GB | Per-user, overridable.                                 |

## Secrets rotation

<AccordionGroup>
  <Accordion title="Rotate SESSION_SECRET">
    Generate a new 32-byte hex value, write it to `.env`, restart the
    panel. All existing sessions are invalidated. Users are signed out
    and need to re-auth.
  </Accordion>
  <Accordion title="Rotate DAEMON_SIGNING_SECRET">
    This is the master secret for daemon JWTs. Rotating it requires
    re-pairing every node. Do not rotate casually — only after a
    suspected compromise.
  </Accordion>
  <Accordion title="Rotate per-node HMAC keys">
    Done from the panel UI: **Admin → Nodes → \[node\] → Rotate key**.
    Atomic, no downtime. See [Pair a node](/self-hosting/pair-node).
  </Accordion>
  <Accordion title="Rotate database password">
    Update `DATABASE_URL`, restart the panel. Postgres connection pool
    drains on shutdown so there's no connection leak.
  </Accordion>
</AccordionGroup>

## Reverse proxy

The bundled Caddy config terminates TLS, serves the panel on `/`, and
proxies `/api` to the panel container. If you bring your own proxy, the
relevant routes are:

| Path        | Backend                  |
| ----------- | ------------------------ |
| `/`         | `apps/web` static bundle |
| `/api/*`    | API on `:8000`           |
| `/healthz`  | API on `:8000`           |

WebSocket upgrade headers must be forwarded for the daemon WS at
`/api/servers/:id/ws`.
