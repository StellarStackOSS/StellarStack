StellarStack is two distinct workloads. **Panel hosts** run the API,
Postgres, and Redis. **Daemon hosts** run game-server containers and the
StellarStack daemon. They can be the same box or different boxes; in
production we recommend separating them so a runaway server can't crash
the panel.

## Panel host

<CardGroup cols={2}>
  <Card title="Minimum" icon="microchip">
    2 vCPU · 2 GB RAM · 20 GB SSD
  </Card>
  <Card title="Recommended" icon="microchip">
    4 vCPU · 4 GB RAM · 40 GB SSD
  </Card>
</CardGroup>

The panel itself is light. Most of its memory budget goes to Postgres's
shared buffers; bigger installs (50+ servers) benefit from giving
Postgres more RAM rather than scaling out replicas.

## Daemon host

Sizing is dictated by the games you run, not by StellarStack. The daemon
itself uses ~50 MB RAM and ~1% of one core; everything else is your
container budget.

Rule of thumb for game servers:

| Game                  | RAM per slot | CPU per slot          |
| --------------------- | ------------ | --------------------- |
| Minecraft (Paper)     | 2–8 GB       | 1 high-clock core     |
| Minecraft (Vanilla)   | 4–12 GB      | 1 high-clock core     |
| Rust                  | 8–16 GB      | 2–4 high-clock cores  |
| Palworld              | 8–16 GB      | 2 cores               |
| Valheim               | 4–8 GB       | 1 core                |
| ARK: Survival Evolved | 8–32 GB      | 2–4 cores             |

Pick CPUs with high single-thread performance. Game-server tick rate is
single-threaded for most engines.

## OS support

StellarStack is tested on the platforms below. The daemon is written in
Go and links against `libdocker` via the Docker socket — it works wherever
Docker Engine itself does.

| OS                  | Architecture     | Panel | Daemon | Notes                                              |
| ------------------- | ---------------- | :---: | :----: | -------------------------------------------------- |
| Ubuntu 22.04 LTS    | amd64 / arm64    |  ✅   |   ✅   | Primary CI target.                                 |
| Ubuntu 24.04 LTS    | amd64 / arm64    |  ✅   |   ✅   | Recommended for new installs.                      |
| Debian 12 (Bookworm) | amd64 / arm64   |  ✅   |   ✅   | Smallest base image.                               |
| Debian 11 (Bullseye) | amd64 / arm64   |  ✅   |   ✅   | Supported until Debian 11 EOL.                     |
| Rocky Linux 9       | amd64            |  ✅   |   ✅   | RHEL-family, SELinux-aware.                        |
| AlmaLinux 9         | amd64            |  ✅   |   ✅   | Same family as Rocky; tested in CI.                |
| Fedora 40+          | amd64 / arm64    |  ⚠️   |   ✅   | Daemon fine; panel works but not tier-1 tested.    |
| Arch Linux          | amd64            |  ⚠️   |   ✅   | Rolling release; daemon AUR package community-maintained. |
| Alpine 3.19+        | amd64 / arm64    |  ⚠️   |   ✅   | Daemon-only recommended; panel runs but glibc-flavoured base images are easier. |
| macOS 13+           | arm64 (M-series) |  ✅   |   ⚠️   | Panel runs natively; daemon works under Docker Desktop but isn't recommended for production. |
| Windows Server 2022 | amd64            |  ❌   |   ❌   | Not supported. WSL2 is daemon-capable but unsupported. |
| Raspberry Pi OS     | arm64            |  ✅   |   ✅   | RPi 4 8 GB or RPi 5 — single-node hobby installs only. |
| FreeBSD 14+         | amd64            |  ❌   |   ❌   | Docker support is too limited.                     |

✅ = supported and tested · ⚠️ = works but not in tier-1 CI · ❌ = not supported.

## Network

| Direction              | Port            | Protocol | Purpose                                |
| ---------------------- | --------------- | -------- | -------------------------------------- |
| Browser → Panel        | 443             | HTTPS    | Panel UI + REST API                    |
| Browser → Daemon       | 8443            | HTTPS/WS | Console, stats, SFTP, file API         |
| API → Daemon           | 8443            | HTTPS    | Install, backup, file ops              |
| Daemon → API           | 443             | HTTPS    | Status callbacks                       |
| Players → Daemon host  | game-specific   | TCP/UDP  | Game traffic; defined per allocation   |

Daemons need a publicly reachable IP for browser connections, but you can
park them behind a Caddy reverse proxy if you'd rather terminate TLS in
one place.

## What StellarStack does *not* need

- **A message queue.** Removed in v2 — schedules and installs run in the
  API process directly.
- **Object storage.** Optional. Backups can stay on the daemon's disk;
  S3 is a "if you want it" target.
- **A second region.** Single-region deployments work great. Multi-region
  is supported but isn't required for HA.
