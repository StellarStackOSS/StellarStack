Every human in StellarStack is a **user**. Users own zero or more
servers and can be invited as **subusers** on other people's servers.
There's no "team" abstraction — the granular unit is the user, and
permissions attach to user × server pairs.

## User roles

| Role         | What they can do                                                  |
| ------------ | ----------------------------------------------------------------- |
| **Admin**    | Everything. Create users, manage nodes, edit any server.          |
| **Operator** | Manage all servers but can't touch users, nodes, or blueprints.   |
| **Member**   | Default. Manage their own servers. Most users live here.          |

Admins are made admins by another admin. The first admin is created by
the installer.

## Creating users

<Tabs>
  <Tab title="Admin invitation">
    **Admin → Users → New**. Enter email + display name. The user
    receives a sign-up link valid for 24h.
  </Tab>
  <Tab title="API">
    `POST /admin/users` with `{ email, displayName, sendInvite: true }`.
    See [API → Authentication](/api-reference/authentication) for tokens.
  </Tab>
  <Tab title="Self-signup">
    Disabled by default. Toggle in **Admin → Settings → Public
    registration** to allow anyone with the panel URL to register.
  </Tab>
</Tabs>

## Per-user limits

Each user has a quota for:

| Quota         | Default | What it caps                                  |
| ------------- | ------- | --------------------------------------------- |
| Servers       | 5       | Max servers they can own.                     |
| Memory        | 16 GB   | Sum across owned servers.                     |
| Disk          | 50 GB   | Sum across owned servers.                     |
| Allocations   | 5       | Total allocations across owned servers.       |
| Backups       | 50      | Total ready backups across owned servers.     |

Limits are checked at create time, not enforced retroactively — bumping
a user's existing servers above the new cap won't auto-delete anything.

Defaults are set in **Admin → Settings**. Per-user overrides live on
the user row.

## Authentication

Email + password is the v1 baseline. 2FA (TOTP) and passkeys
(WebAuthn) are available — see [Two-factor](/security/two-factor) and
[Passkeys](/security/passkeys).

OAuth providers (Google, GitHub, etc.) are deferred to v2.

## Sessions

Sessions are cookie-backed, signed with `SESSION_SECRET`. Cookie
attributes:

- `Secure`: yes (panels must run over HTTPS).
- `HttpOnly`: yes.
- `SameSite=Lax`: protects against CSRF on top of CSRF tokens for
  state-changing routes.
- Expiry: 30 days; rolling on activity.

Logging out invalidates the session immediately.

## Deleting users

Hard-deleting a user cascades into:

- Their owned servers — admin chooses to **transfer to another user**
  or **delete with their files**.
- Their subuser memberships — removed silently.
- Their audit-log entries — kept (with the user ID retained), so
  history isn't rewritten.

The UI prefers the transfer path; outright file deletion needs explicit
confirmation.
