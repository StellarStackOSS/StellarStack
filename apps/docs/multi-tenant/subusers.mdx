A **subuser** is a regular user who's been granted access to someone
else's server. They sign in with their own panel account; the access is
the relationship, not a separate login.

Subusers are the answer to "let my friend restart the Minecraft server
when I'm asleep" without sharing your full panel password.

## Inviting

**Server → Settings → Subusers → Invite**.

1. Enter the invitee's email. They must already have a panel account
   (or an admin creates one for them).
2. Pick the scopes to grant — see [Permissions](/multi-tenant/permissions)
   for the list.
3. Send the invite. They appear immediately in the subuser list and
   receive a notification email.

There's no separate "accept invite" step — once added, they can use
the server within their granted scopes.

## Managing scopes

Each subuser row has the granted scopes inline; clicking edits them.
Changes take effect on the subuser's next request — already-open
browser sessions get re-authed against the new scope set.

## Common scope bundles

| Use case                | Scopes                                              |
| ----------------------- | --------------------------------------------------- |
| Console-only watcher    | `console.read`                                      |
| Console operator        | `console.read`, `console.write`                     |
| Power operator          | `console.*`, `control.start`, `control.stop`        |
| File editor             | `console.read`, `files.read`, `files.write`         |
| Backup admin            | `backups.*`                                         |
| Full delegate           | All scopes except `server.delete` and `subusers.*`  |

The panel UI offers these as preset bundles for quick assignment.

## What subusers can never do

| Action                          | Reason                                                   |
| ------------------------------- | -------------------------------------------------------- |
| Delete the server               | Owner-only (or admin override).                          |
| Add or remove other subusers    | Owner-only by default; grantable via `subusers.*`.       |
| Change the blueprint            | Major operational change; owner-only.                    |
| Transfer ownership              | Owner-only.                                              |

Even an "all scopes" subuser is still a subuser, not the owner.

## Audit trail

Every subuser action is logged with the actor's user ID. The audit log
makes it obvious who did what — useful when a server's misconfigured
and you want to know which co-admin pressed which button.

## Removing

**Server → Subusers → \[user\] → Remove**. Immediate. The subuser's
panel session for *this* server is invalidated within seconds. Their
own servers and other subuser memberships are unaffected.
